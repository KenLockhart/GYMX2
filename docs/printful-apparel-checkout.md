# Apparel checkout and Printful-only fulfillment

This runbook describes the apparel-checkout implementation and its current verification status. It is not approval to launch. Customers may purchase only explicitly published, curated apparel previews with a separately approved exact-variant manifest. Publishing a preview alone does not make it purchasable.

## Customer and fulfillment path

The guest chooses an available color and size combination. The server resolves its opaque local variant UUID to the currently approved Printful sync variant, obtains a fresh US order-cost estimate for the exact variant and recipient, and creates a card-only Stripe Checkout session. Customer shipping remains free. Customer copy may say “Made to order; allow 3–4 weeks for delivery.”

A verified, matching Stripe payment event records the order and queues durable work. The worker rechecks payment, address, approval, design identity, availability, provider cost, and the approved supplier-cost cap. It creates a native Printful order draft, validates the observable order facts, and confirms only when cost remains within the cap and verified Stripe net proceeds. Uncertain outcomes are reconciled by the saved external order identity; they are not retried with a new order identity. Printful apparel orders do not fall back to manual fulfillment. Historical purchases and digital commerce are preserved.

Printful products are never created automatically. An administrator first selects an existing store product into private staging, reviews costs, curates copy and an approved local image, explicitly publishes its display-only preview, then separately approves the exact apparel variants for sale. Initial variant approval requires a fresh, scalar UI cost review tied to the observed configuration; ranges remain unapproved. After approval, an unchanged approved variant may use a fresh, request-bound server API estimate even when its UI review has aged. A new or unapproved variant, changed approval/configuration, unavailable variant, or missing, stale, or mismatched API quote stays ineligible. Catalog refresh preserves local curation and identifiers; it does not adopt an ordinary product by title or SKU.

The apparel-only cutover blocks new physical manual checkout. Before cutover, resolve open physical payment sessions and late-paid events; unresolved paid legacy sessions block activation. Existing historical orders and digital purchases remain intact. The configured failure policy is `admin_review`; the admin exception list is read-only and provides no refund or manual-fulfillment action.
