## Processing contract

- Load the package, model, and Worker only after an explicit user start. The product component dynamically imports `browser-runtime.ts`; the runtime loads its Worker manifest and constructs the dedicated Worker only after the user action. The common component is not mounted on dashboard/shared layout or product routes in this packet.
- Run the pose detector in `VIDEO` mode and call `detectForVideo` with a strictly increasing timestamp: live input uses `requestVideoFrameCallback`’s monotonic `now`; recorded/reference input uses finite, strictly increasing `mediaTime` PTS and stops on seek/replay/discontinuity. Never use `Date.now()` or inference completion time as exercise tempo. Send only one in-flight frame to the Worker; close each transferred `ImageBitmap` and each segmentation result in `finally`; do not keep a backlog.
- Select Lite for a coarse-pointer/mobile or unknown capability profile and Full for a capable desktop profile. Keep the choice local and per session; do not persist or transmit device metadata. Try GPU in the dedicated Worker first; verified cleanup allows CPU fallback in that Worker. Uncertain cleanup requires terminating it and starting a fresh CPU Worker. If Worker/OffscreenCanvas or CPU support is absent, stop with a supported-device message. Do not move inference onto the main thread or a hosted service.
- Feature-detect `Worker`, `OffscreenCanvas`, transferred canvas, and the requested GPU context. GPU and CPU inference have both been exercised in a desktop browser with synthetic canvas video. On stop/unmount/error, cancel frame callbacks, close frames/results, close the detector, and terminate the Worker. The generic processor never requests camera/microphone permission or stops caller-owned live-stream tracks; it clears its `video.srcObject`. A caller that owns media must stop its own tracks.
- Use the existing set-bounded `CurlRepSegmenter`: 30,000 samples by default, then typed `session_sample_limit`. Surface a set-boundary notice, aggregate the scores the user wants to keep, and explicitly reset for the next set. Raw frames/landmarks and raw per-frame curves stay ephemeral and are never uploaded; only bounded numeric rep summaries may be used by later, separately authorized result persistence.
- Target 20 processed FPS on supported physical devices. Permit at most one frame in flight; count local dropped-frame totals without retaining frames. Sustained performance below 15 FPS for 3 seconds triggers a visible slow-processing notice. Do not silently claim the target or silently switch models mid-set.

## Verification and release gates

If GPU cleanup is uncertain, the runtime terminates the failed Worker and starts a fresh CPU Worker without creating a GPU context.

The pure FPS helper counts processed-frame completion events in `(max(sessionStart, now - windowMs), now]` with the left boundary excluded; the observation duration includes time since the latest frame, so a stalled stream decays before the window empties. It is now wired to Worker completion events. A synthetic desktop browser smoke run observed about 29 GPU FPS and 16 CPU FPS; neither is a physical phone/device guarantee.

## Bilateral runtime and numeric timing contract (2026-11-20)

- `arm: "both"` now runs two separate smoothers, setup baselines, metric streams, and rep segmenters. Both shoulders, elbows, and wrists must remain visible; each arm also needs the ear and hip metrics required by the posture scorer. Both independent two-second setup holds must finish before the processor reports ready. `arm: "auto"` retains its one-second visibility lock. The configured `cameraView` now travels from `FormCoachProcessor` through the browser runtime into Worker initialization; the default standing curl still requires a side view.
- A bilateral rep is counted only after each arm has produced a complete extended-to-flexed-to-extended segment. Starts and ends must be within 350 ms, each phase duration within the greater of 250 ms or 30%, ROM endpoints within 25 degrees with a nonempty ROM intersection, and the average pointwise elbow-curve difference within 20 degrees after 50-point resampling. One unmatched completed segment waits at most one second. Missing partners, out-of-phase motion, phase mismatch, or shape/range asymmetry produce a rejection status and no rep count. Missing visibility or a frame gap over 500 ms invalidates partial candidates and clears unmatched pair state, so a partial or dropped cycle cannot pair with a later repetition.
- Paired scores use the lower arm score and lower score for each component; faults are unioned, movement deviations use the larger side, ROM uses the intersection, and phase times/curves are averaged only after passing the pair bounds. Reference construction accepts only clean paired cycles and builds its median from three to five pairs. Raw arm curves stay inside the Worker/engine; the result DTO contains only bounded numeric metrics.
