## Processing contract

- Load the package, model, and Worker only after an explicit user start on the coach template-processing page or member session page. Use dynamic import so dashboard and other pages do not download any runtime chunk or asset.
- Run the pose detector in `VIDEO` mode and call `detectForVideo` with a strictly increasing monotonic timestamp captured from `requestVideoFrameCallback`’s high-resolution `now` (or an equivalently verified monotonic capture clock). Do not use `Date.now()` or an unverified media-time clock. Send only one in-flight frame to the Worker; close each transferred `VideoFrame`/`ImageBitmap` in `finally`, and do not keep a backlog.
- Select Lite for a coarse-pointer/mobile or unknown capability profile and Full for a capable desktop profile. Keep the choice local and per session; do not persist or transmit device metadata. Try GPU in the dedicated Worker first; on initialization failure close the detector and Worker resources, then retry CPU in the Worker. If Worker/OffscreenCanvas or CPU support is absent, stop with a supported-device message. Do not move expensive inference silently onto the main thread or fall back to a hosted service.
- Feature-detect `Worker`, `OffscreenCanvas`, canvas transfer, and the requested GPU context. Exercise both GPU and CPU paths in browser tests. On stop/unmount/error, cancel frame callbacks, close detector and current frame, terminate Worker, stop camera tracks, clear `video.srcObject`, and reject stale Worker messages. A Worker error must leave no active camera or queued frames.
- Use the existing set-bounded `CurlRepSegmenter`: 30,000 samples by default, then typed `session_sample_limit`. Surface a set-boundary notice, aggregate the scores the user wants to keep, and explicitly reset for the next set. Raw frames/landmarks and raw per-frame curves stay ephemeral and are never uploaded; only bounded numeric rep summaries may be used by later, separately authorized result persistence.
- Target 20 processed FPS on supported physical devices. Permit at most one frame in flight; count local dropped-frame totals without retaining frames. Sustained performance below 15 FPS for 3 seconds triggers a visible slow-processing notice. Do not silently claim the target or silently switch models mid-set.

## CSP and network gate

- Keep coach reference processing and member live sessions as two explicit same-origin consumers. Their approved network calls are separate from pose processing: existing auth/session calls and, later, authorized template/attempt JSON APIs may remain; neither request body may contain a frame, `ImageBitmap`, `VideoFrame`, raw landmark array, or per-frame pose history. Do not import RealtimeKit or other meeting SDKs into either Form Coach runtime.
- Add a coach/session-only nonce CSP through the current Proxy flow, preserving Supabase `Set-Cookie` behavior. The page policy must include a narrowly scoped `worker-src 'self'`; `connect-src` may include only same-origin runtime assets and the already-required app API origins. Do not add Google or a model CDN. Keep `blob:` out unless the actual emitted Worker requires it and privacy/security review approves it.
- A page CSP alone is insufficient. First build a minimal module Worker from `new Worker(new URL(..., import.meta.url), { type: "module" })` under this App Router/Turbopack configuration. Inspect the actual emitted bundle reference and browser request URL with the default config, then repeat with the documented `turbopackWorkerAssetPrefix` if needed. Its effect on the actual Worker URL is not verified yet. Do not treat a setting or HTML string as proof: the first gate is the real emitted Worker request plus its response headers. Only after that path is proven should a narrowly matched `next.config.ts` `headers()` response policy be added for the emitted Worker path. The Worker response policy must default-deny and allow only same-origin scripts/connections plus `wasm-unsafe-eval` if the exact runtime requires it. If the URL/prefix cannot be targeted or the response CSP is absent, stop; do not widen policy to all `/_next/static` assets or rely on parent-page CSP.
- The current MediaPipe Terms of Service ([official terms](https://developers.google.com/edge/mediapipe/legal/tos), updated 2026-11-04 per current review) describe periodic Google contact and usage/performance/application/input metadata. No telemetry-off option has been verified for 1.2.3. Self-hosting does not prove the runtime makes no external request and does not resolve those terms. Audit the exact pinned package and models with cross-origin requests blocked. If inference fails when external calls are denied, or the terms require data flow not approved by the privacy owner, stop for that decision; do not enable telemetry or claim “all local.”
